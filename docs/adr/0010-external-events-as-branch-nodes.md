# ADR 0010: 外部イベントをブランチノードとして表示

## ステータス

承認済み

## コンテキスト

`exec_command_end`、`mcp_tool_call_end`、`view_image_tool_call` 等の**外部イベント**（call_idを持つイベント）が存在する。
これらはツール呼び出し（`function_call`）と `call_id` で紐付けられている。

これらの外部イベントをどのように表示するか決定する必要がある。

## 決定

外部イベントを、対応するアクションノード（`function_call_output` 等）の右側に**ブランチノード**として表示する。

`step` エッジでアクションノードから分岐して接続する。

## 理由

### 採用理由

1. **補助情報としての性質**
   - 外部イベントはツール呼び出しの「結果」や「補助情報」であり、メインフローに含めるべきではない

2. **関連性の視覚的明確化**
   - ツール呼び出し（`function_call`）とその完了イベントの関連性を視覚的に明確にする

3. **メインフローのシンプルさ**
   - ハーネス上のノード数を抑制し、メインフローをシンプルに保つ

4. **出現順序の柔軟性**
   - 外部イベントの出現順序は固定ではなく、ツール呼び出しの直後とは限らない場合があるため、分岐表示の方が柔軟

### 検討した代替案

| 案 | 内容 | 採用見送りの理由 |
|------|------|------------------|
| 案B | 外部イベントを独立ノードとしてハーネス上に配置する | メインフローが複雑になる、ツール呼び出しとの関連性が分かりにくくなる |

## 結果

- 外部イベントは `call_id` で対応するアクションノードと紐付けられる
- ブランチノードは対応するアクションノードの右側に配置
- `step` エッジでアクションノードから分岐
- ステータス表示（exit_code=0 → ✓、0以外 → ✕、result.Ok → ✓、result.Err → ✕）

## 関連決定

なし
