# ADR 0026: 完全オフライン動作とアップデートポリシーの決定

## ステータス

承認済み

## コンテキスト

要件定義書（§1.4, §3.1）にて、本アプリケーションはローカル完結で動作し、外部サーバーへのデータ送信は一切行わないことが義務付けられている。
このセキュリティ・プライバシー保護の前提において、新しいバージョンがリリースされた際のアップデート通知や自動更新（一般的にインターネット経由の外部APIリクエストを伴う）の実装方針を定義する必要がある。

## 決定

1. **完全オフライン動作（インターネット通信の排除）**:
   アプリケーション内部から、インターネット上のいかなる外部サーバー（GitHub Releases API等を含む）に対しても、自動または非同期の通信リクエストを送信しない。
2. **アップデート検知機能の非搭載**:
   新バージョンの自動チェック機能や自動アップデート機能は一切実装しない。
3. **手動アップデートの運用**:
   アプリケーションの更新は、ユーザーが配布元（GitHubのリリース等）から新しいバイナリ/インストーラーを手動でダウンロードし、再インストールする運用とする。

## 理由

1. **ローカル完結要件の厳格な順守**:
   いかなる外部通信も発生させないことで、企業のセキュリティポリシーや閉域網環境下でも安全かつ確実に動作することを保証する。
2. **セキュリティリスクの極小化**:
   自動更新や外部APIの問い合わせを排除することで、サプライチェーン攻撃（不正なアップデートによるマルウェア混入等）や、中間者攻撃（MitM）による通信傍受のリスクを完全にゼロにできる。
3. **実装の簡素化**:
   コード署名やアップデートパッケージの暗号化検証、OSごとの管理者権限昇格など、自動アップデートに伴う多大な開発コストと保守オーバーヘッドを避けることができる。
