# ADR 0028: ノードバッジにノード消費トークン数を表示

## ステータス

承認済み

## コンテキスト

従来のノードバッジは、紐付く最後の `token_count` の
`total_token_usage.total_tokens` を表示していた。この値はセッション累計であり、
ノード自体の消費量を示さない。さらに同一ノードへ複数の `token_count` が紐付く場合、
件数は表示されるが各回の消費量は集約されていなかった。

## 決定

- ノードバッジ値を、当該ノードに紐付く全 `token_count` の
  `last_token_usage.total_tokens` の合計とする。
- `last_token_usage` が欠落したレコードは合計へ加算しない。
- `boundCount` は欠落値を含む全レコード件数とし、従来の `×N` 表示を維持する。
- APIフィールドを `totalTokens` から `consumedTokens` へ改名する。
- 右パネルとセッション統計の累計値は従来どおり
  `total_token_usage` および `statistics.total_tokens` を使用する。
- 旧APIフィールドを含むキャッシュの誤表示を防ぐため、
  セッション詳細キャッシュスキーマをバージョン2へ更新する。

## 理由

`last_token_usage` は各API呼び出しラウンドの消費量を表すため、ノード単位の分析に
適している。API名に `consumed` を含めることで、セッション累計との意味の違いも
明確になる。

## 結果

- バッジからノード単位の消費量を比較できる。
- 欠落レコードが存在しても既知の消費量と紐付け件数を失わない。
- キャッシュスキーマ更新後の初回表示ではJSONLが再解析される。

## 関連決定

- ADR 0004: キャッシュ形式をReact Flow形式にする
- ADR 0005: token_countをバッジとして表示
