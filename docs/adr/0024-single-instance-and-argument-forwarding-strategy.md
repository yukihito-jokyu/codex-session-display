# ADR 0024: シングルインスタンス起動制御と引数転送戦略の決定

## ステータス

承認済み

## コンテキスト

デスクトップアプリケーションとして、複数のインスタンスが同時に起動すると、キャッシュファイル（`~/.codex-display/{sessionID}.json`）やログファイルへの同時書き込みによる競合・破損が発生する懸念がある。
また、OSのファイル関連付けやコマンドライン引数経由で特定のセッションファイルを指定して起動した際、既にアプリケーションのウィンドウが開いている場合は、新しくウィンドウを開くのではなく、既に開いているウィンドウ内でそのセッションを表示させることがユーザー体験（UX）の観点から望ましい。

## 決定

1. **TCPソケットを用いた多重起動検知**:
   アプリケーション起動の最序盤（`main.go` のエントリポイント）で、ローカルループバックアドレスの特定のポート（`localhost:58385`）に対する TCP リスナーの取得（`net.Listen`）を試みる。
2. **メインインスタンス（最初の起動）の挙動**:
   ポートの取得に成功した場合、自身を「メインインスタンス」と位置づけ、Wailsアプリケーションの初期化および起動処理に進む。同時に、バックグラウンドの goroutine で TCP ポートを監視し続け、後続インスタンスから受信する引数（ファイルパス）を待ち受ける。
3. **サブインスタンス（二重起動）の挙動**:
   ポートの取得に失敗した場合（既にポートが使用中＝別インスタンスが起動済み）、自身を「二重起動されたインスタンス」と判定する。コマンドライン引数（`os.Args`）からセッションログのファイルパス（存在する場合）を取得し、確立されたソケット経由で既存のメインインスタンスへ送信し、送信完了後に自身は即座に終了する（Wailsウィンドウは生成しない）。
4. **イベント通知とウィンドウフォーカスによる画面切り替え**:
   - メインインスタンスが TCP ポートからファイルパスを受信した際、Wailsのイベントエミッター（`runtime.EventsEmit`）を用いてフロントエンドに受信イベント（例: `open-session-file`）を送信する。
   - 同時に、Wailsランタイム API（`runtime.WindowShow`）を呼び出してウィンドウを最前面にフォーカスさせる。
   - フロントエンド（React）側は、イベント受信時に該当ファイルパスの解析・読み込み要求をバックエンド（`GetSessionDetail`）へ送り、表示画面を受信したセッションに切り替える。

## 理由

1. **データの不整合・競合の防止**:
   単一のインスタンスのみが書き込みを行うようにすることで、キャッシュファイルやログファイルの競合による破損リスクを根本的に排除できる。
2. **シームレスなマルチタスクUX**:
   ユーザーがOSのファイラー（Finderやエクスプローラー等）やターミナルから新しいセッションファイルを次々と開いた際、余分なウィンドウが増えることなく、既存のウィンドウが最前面に表示されてコンテンツが即座に切り替わる、ネイティブアプリらしい軽快な体験を提供できる。
3. **プラットフォーム非依存の実装**:
   OS固有のプロセス間通信（IPC）やファイルロックAPIを使用する代わりに、すべての主要OS（macOS, Windows, Linux）で標準サポートされている TCP ループバックソケットを利用することで、CGOやOSごとの条件分岐を伴わないシンプルかつポータブルな実装を維持できる。
