# ADR 0016: 画像エクスポート機能の保留と画面内統計グラフ表示への切り替え

## ステータス

承認済み

## コンテキスト

要件定義書（`requirements.md`）では可視化結果を画像としてエクスポートする要件があり、詳細設計書（`detailed-design.md`）ではGoバックエンドによる「6つの統計カード」を並べたPNG画像の生成（`ExportStatsImage` API）が定義されていた。

しかし、以下の課題が明らかになった：
1. **キャンバス画像化の難易度**: React Flowキャンバス全体をクライアント側で綺麗に画像化するには、CSS変数や動的SVGエッジの再現性、画面外ノードの描画などのバグが発生しやすく、実装コストに対して保守性が低い。
2. **Goバックエンドでの描画制限**: Goバックエンドで統計情報に加えて「ターンごとのトークン消費量」や「ツール呼び出し回数」のグラフを描画する場合、グラフ用ライブラリの追加依存やマルチプラットフォームでの日本語フォント解決などの複雑な課題が発生する。
3. **分析上の価値**: ユーザーへのヒアリングにより、静的な要約画像エクスポートよりも、「ターンごとのトークン消費量」や「ツール呼び出し回数」といったセッション分析に直結するグラフ（チャート）をアプリ画面上で直接確認できる方が価値が高いと判断された。

## 決定

1. **画像エクスポート（PNG出力）機能の保留**:
   - `ExportStatsImage` APIの設計およびエクスポートボタン、ファイル保存ダイアログの実装を一旦保留（スコープ外）とする。
2. **画面内での統計グラフ表示の追加**:
   - セッション詳細画面の右パネル等に、ターンごとの「トークン消費量」および「ツール呼び出し回数」を視覚的に表現するインタラクティブなグラフ（チャート）を配置する。

## 理由

1. **実装の確実性と保守性**:
   - 画像化ライブラリ（`html-to-image` 等）の依存やキャンバスキャプチャの複雑さ、Go側での画像生成ロジックの作り込みを避けることで、開発工数を大幅に削減しバグのリスクを最小化する。
2. **ユーザー体験の向上**:
   - ファイルとして書き出す手間に比べ、アプリを開いてその場で推移グラフを分析・インタラクションできる方が、エージェントのトークン消費分析ツールとして本質的であるため。

## 検討した代替案

| 候補 | 採用見送りの理由 |
| :--- | :--- |
| **フロントエンド画像化（html-to-image） + バックエンド保存** | 実装は比較的容易だが、グラフ表示自体が画面内にあれば十分であり、ローカルデスクトップアプリという性質上、画像を外部に共有するニーズが低く、一旦画像化する機能自体の優先度が低いと判断したため。 |
| **バックエンド自前描画（Go 2Dグラフィックス）** | 折れ線グラフや棒グラフを描画するロジックをGoで実装するのはレイアウトやフォントの調整コストが極めて大きく、グラフの見た目もフロントエンドのモダンなUIに揃えるのが困難なため。 |
