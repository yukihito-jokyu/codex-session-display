# ADR 0003: レイアウト計算をバックエンドで行う

## ステータス

承認済み

## コンテキスト

React Flowで可視化するノードの座標（X, Y）をどこで計算するか決定する必要がある。
ノードは数百〜数千件に及ぶ可能性があり、複雑なツリー構造（fork-joinパターン等）を持つ。

## 決定

**バックエンド（Go）で固定座標を計算**し、フロントエンドはそのまま配置する。

## 理由

### 採用理由

1. **一貫性のあるレイアウトの保証**
   - キャッシュから読み込んだ際に同じ配置になる

2. **パフォーマンス**
   - フロントエンドでのレイアウト計算コストを回避

3. **キャッシュ形式への座標情報の含めることによる柔軟性**
   - 将来的にレイアウトの永続化が可能になる
   - ユーザーが手動でレイアウト調整した場合の保存等、将来的な拡張に備えられる

### 検討した代替案

| 案 | 内容 | 採用見送りの理由 |
|------|------|------------------|
| 案B | バックエンドはノードの階層構造のみを返し、フロントエンドでReact Flowの自動レイアウト機能を使う | React Flowの自動レイアウト機能が複雑なツリー構造（fork-joinパターン等）に対応していない |
| 案C | バックエンドは相対的な順序情報のみを返し、フロントエンドで動的にレイアウトを計算する | 一貫性のあるレイアウトが保証されない、フロントエンドの処理コストが増加 |

## 結果

- バックエンドでノードの座標（Position）を計算する
- レイアウト定数（HarnessX, BranchOffsetX, NodeWidth等）はバックエンドで定義
- フロントエンドはReact Flowの自動レイアウト機能を使用しない（ズーム・パンのみ）
