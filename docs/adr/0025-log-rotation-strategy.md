# ADR 0025: 起動時の簡易ログローテーション戦略の決定

## ステータス

承認済み

## コンテキスト

ADR 0021にて、本番環境におけるログ出力先を `~/.codex-display/logs/app.log` と決定した。しかし、デスクトップアプリケーションの長期利用に伴い、ログファイルが肥大化してユーザーのディスク容量を圧迫するリスクがある。
一方で、ADR 0013の「依存ライブラリを最小限（`go-json` のみ）にする」方針を順守するため、ログローテーションのためにサードパーティ製ライブラリを新規導入することは避けたい。

## 決定

1. **起動時のサイズ判定（セルフローテーション）**:
   アプリケーションの起動処理の初期段階（ロガー設定の前）で、Goバックエンドにて `~/.codex-display/logs/app.log` のファイルサイズを確認する。
2. **ローテーションしきい値と世代管理**:
   ファイルサイズが **10MB**（10,485,760 バイト）を超えている場合、以下の手順でローテーションを実行する。
   - 既存の `~/.codex-display/logs/app.log.1`（古い世代）が存在する場合は削除する。
   - 現在の `~/.codex-display/logs/app.log` を `~/.codex-display/logs/app.log.1` にリネーム（退避）する。
   - 新規に空の `~/.codex-display/logs/app.log` を作成し、ログ出力を開始する。
3. **標準ライブラリによる実装**:
   外部のログローテーションライブラリは導入せず、Go標準ライブラリの `os` パッケージ（`os.Stat`, `os.Remove`, `os.Rename`）のみを用いてシンプルに実装する。実行中のリアルタイムなファイルサイズ監視・切り替えは行わず、起動時の1回のみ実行する。

## 理由

1. **ゼロ依存関係の維持**:
   サードパーティ製ライブラリを追加することなく、ディスクの圧迫問題を解決できるため、コードベースの軽量性と安全性を高く維持できる（ADR 0013の要件を満たす）。
2. **実装のシンプルさと安全性の確保**:
   実行中にバックグラウンドスレッドでファイルサイズをリアルタイムに監視し、書き込み中にファイルを切り替える処理は、ファイルの排他ロックや同時書き込み時の不整合を防ぐための複雑な同期制御が必要になる。
   起動時の単一スレッドで実行するワンタイム処理に留めることで、競合が一切ないクリーンな状態で、かつわずか数十行の安全なコードで実装を完了できる。
