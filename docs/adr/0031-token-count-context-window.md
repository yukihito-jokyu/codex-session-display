# ADR 0031: token_count単位のコンテキスト上限をDTOへ保持する

## ステータス

承認済み

## コンテキスト

コンテキスト使用率は各 `token_count` の入力トークン数とモデル上限から算出する。
セッション統計の上限だけを使うと、ターンやtoken_countで上限が変わる記録を正しく表示できない。
一方、JSONLにはtoken_count側の上限がない記録も存在する。

## 決定

- `TokenCountEntry` に `model_context_window` を追加する。
- 正の `token_count.info.model_context_window` を優先し、無効なら所属ターンの正の
  `task_started.model_context_window` へフォールバックする。
- 有効な上限がなければ0を返す。
- フロントエンドは `last_token_usage.input_tokens / model_context_window * 100` で
  表示用の使用率を導出し、キャッシュ済み入力を差し引かず、100%でクランプしない。
- DTO変更に伴いセッション詳細キャッシュスキーマを6へ更新する。

## 理由

上限の解決はターン構造を把握しているバックエンドで確定し、表示用の比率は
チャート要件を所有するフロントエンドで導出することで、DTOには元データを保持しつつ
欠落時の優先順位を一箇所に集約できる。

## 結果

- スキーマ5以前のキャッシュは初回表示時に再解析される。
- 算出不能な点は0%と区別して非描画にできる。
- 有効なContext Usage点は既存のtoken_count共通選択経路を利用する。
