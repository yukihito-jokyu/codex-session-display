# ADR 0004: キャッシュ形式としてReact Flow形式を採用

## ステータス

承認済み

## コンテキスト

JSONLパース結果を `~/.codex-display` にキャッシュ保存する必要がある。
キャッシュにどのような形式を採用するか決定する必要がある。

## 決定

**React Flow形式（nodes/edgesを含む）**をキャッシュ形式として採用する。

キャッシュファイルの中身は `GetSessionDetail` APIのレスポンス（SessionDetailResponse）と同一形式とする。

## 理由

### 採用理由

1. **変換処理（FlowGraph生成）コストの回避**
   - パース済みの構造化データからReact Flow形式への変換コストを回避

2. **レイアウト計算（座標計算）コストの回避**
   - 座標計算のコストを回避

3. **キャッシュヒット時の処理の単純化**
   - キャッシュ形式をAPIレスポンスと一致させることで、キャッシュヒット時はファイル読み込み→返送のみで済む

4. **フロントエンド実装の簡素化**
   - フロントエンドで追加の変換処理が不要

### 検討した代替案

| 案 | 内容 | 採用見送りの理由 |
|------|------|------------------|
| 案B | パース済みの構造化データ（ParsedSession）のみをキャッシュし、フロントエンドでReact Flow形式に変換する | 変換コストが毎回発生する、フロントエンドの処理が複雑になる |

## 結果

- キャッシュファイル: `~/.codex-display/{sessionID}.json`
- キャッシュ内容: SessionDetailResponse（cache_schema_version, nodes, edges, statistics, token_counts）
- 再パース判定: キャッシュスキーマバージョンが現行と異なる、または JSONLファイルの最終更新日時 > キャッシュファイルの最終更新日時
