# ADR 0030: セッション詳細の表示単位を共通選択する

## ステータス

承認済み

## コンテキスト

タイムライン、React Flow、token_count統計、BottomPanelは同じJSONL記録を異なる粒度で
表示している。フロントエンドが本文やラベルから対応関係を推測すると、tool batchや
重複会話、複数token_countを一意に解決できない。

## 決定

- バックエンドが各 `ConversationTimelineItem` に `selection_id`, `node_id`,
  `node_ids`, `token_count_indices` を付与する。
- `selection_id` はターン番号と代表行番号から安定生成する。
- `node_ids` は表示単位に含まれる全ノード、`node_id` はズーム対象の代表ノードとする。
- フロントエンドは単一の共通選択状態からタイムライン、キャンバス、統計、BottomPanelを導出する。
- タイムラインだけを外部選択時に自動スクロールし、右側統計パネルは自動スクロールしない。
- DTO変更に伴いセッション詳細キャッシュスキーマを5へ更新する。

## 理由

対応関係をレコード解析済みのバックエンドで確定すると、表示領域ごとの推測処理を避け、
複数ノード・複数token_countを含む表示単位も集合として一貫して選択できる。

## 結果

- スキーマ4以前のキャッシュは初回表示時に再解析される。
- タイムライン表示単位を追加・変更する場合は、選択IDと対応集合も同時に生成する必要がある。
- 右側統計パネルの現在位置は選択操作で変化しない。

## 関連決定

- ADR 0027: 表示単位は元レコード順を保持する
- ADR 0029: 会話タイムラインの表示単位をバックエンドで確定する
