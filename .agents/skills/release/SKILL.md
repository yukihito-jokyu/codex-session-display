# リリース自動化スキル

このスキルは、`codex-session-display` アプリケーションの新しいバージョンをリリースする手順を自動化・案内するためのものです。リリースは、バージョンタグのプッシュをトリガーとして GitHub Actions により完全に自動化されます。

## 哲学と基本原則

- **自動化第一**: ローカルでバイナリをビルドしたり、手動でリリースを作成したりしないでください。必ずリリースタグ（`vX.Y.Z`）をプッシュし、GitHub Actions 経由でリリースビルドを実行してください。
- **セマンティックバージョニングの厳守**: `vX.Y.Z` 形式に従い、変更内容の重要度に基づいてバージョンを決定します。
  - メジャー（X）: 互換性のない API やデータ構造の変更
  - マイナー（Y）: 後方互換性のある機能追加（例：今回の自動アップデート機能の追加など）
  - パッチ（Z）: 後方互換性のあるバグ修正

## ワークフロー手順

### 1. 現在の最新バージョンとコミット履歴の確認

現在の最新バージョンタグを確認し、前回のリリース以降のコミットログを取得して変更内容を整理します。

```bash
# 最新のタグを確認
git describe --tags --abbrev=0

# 前回タグから現在（HEAD）までのコミットログを確認
git log $(git describe --tags --abbrev=0)..HEAD --oneline
```

### 2. リリースバージョンの提案と合意形成

コミット履歴から変更内容（機能追加, バグ修正, 破壊的変更）を分析し、次に適用すべきバージョン番号を決定します。
決定したバージョンと、そのバージョンでリリースされる変更内容の概要（リリースノート案）をユーザーに提示し、リリース実行の承認を得てください。

### 3. リモート・ローカルの同期と最終検証

リリースを実行する前に、現在のブランチ（通常は `main`）が最新であり、すべてのテストがパスしていることを確認します。

```bash
# 最新の変更をプル
git checkout main
git pull origin main

# リンターとテストを実行
task lint
task test
task test:e2e
```

すべての検証がグリーンであることを確認します。失敗しているテストがある場合は、リリースを進めてはいけません。

### 4. タグの作成とプッシュ

ユーザーからの承認を得た後、決定したバージョンで Git タグを作成し、リモートにプッシュします。

```bash
# 例: v1.1.0 をリリースする場合
git tag v1.1.0
git push origin v1.1.0
```

### 5. リリース状況の監視

タグがプッシュされたら、GitHub Actions（`release.yml`）が起動します。GitHub CLI (`gh`) を使用して、ワークフローの実行状況を監視します。

```bash
# リリースワークフローの進捗を確認
gh run list --workflow=release.yml --limit=3
```

ビルドが成功し、GitHub Releases にアセット（`.dmg` および `.zip`）が添付されて即時公開されたことを確認後、ユーザーにリリース完了を報告します。

## チェックリスト

リリースを実行するエージェントは、以下のチェックリストを順に確認してください：

- [ ] 最新の Git タグと変更履歴を確認したか？
- [ ] 次のバージョンがセマンティックバージョニングに則っているか？
- [ ] リリースバージョンとリリースノート案についてユーザーの合意を得たか？
- [ ] ローカルおよびリモートが最新の main ブランチになっているか？
- [ ] `task lint` / `task test` / `task test:e2e` がすべてグリーンであるか？
- [ ] Git タグをプッシュしたか？
- [ ] GitHub Actions ワークフローが成功し、リリースが正常公開されたことを確認したか？
