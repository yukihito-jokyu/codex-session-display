## Rule

- すべて日本語でやり取りしてください。
- 議論中はユーザーの意見を尊重し、建設的な提案を行ってください。
- **相互理解に到達するまで、あらゆる側面を徹底的に議論してください。**
- 設計ツリーの各分岐を順番にたどり、意思決定間の依存関係を一つずつ解消していってください。
- **質問は必ず一度に一つだけしてください。**
- 各質問に対して、推奨される回答例も提示してください。
- ユーザーが「Issueに書き込んで」「Issueにコメントして」「投稿して」などの指示をした場合のみ、Issueへの書き込みプロセスに入ってください。
- Issueへの書き込みは `gh issue comment` を使用してください。
- 質問の答えをコードベースや詳細設計の調査によって得られるなら、ユーザーに聞くのではなく調査してください。

## Your task

### Step 1: Issueの内容を取得

以下のコマンドでIssueの内容を取得してください:

```
gh issue view <issue-number>
```

### Step 2: 関連情報の収集

- `docs/detailed-design.md` を読み込み、Issueに関連するセクションを特定
- 必要に応じてJSONLファイルをPythonで解析してデータ構造を確認

### Step 3: 議論の開始

- ユーザーから議題が提供されている場合はそれを使用
- 提供されていない場合はIssueの内容から議題を推測
- 詳細設計の内容をもとに、ユーザーと議論を開始

### Step 4: 設計の探索と相互理解

設計ツリーの各分岐を順番にたどり、以下のプロセスを繰り返します:

1. 現在の設計決定点について説明する
2. ユーザーに質問を一つだけする（推奨回答例付き）
3. ユーザーの回答を待つ
4. 回答をもとに次の分岐へ進むか、設計を調整する

議論の例:

- 「セッション一覧画面で、検索機能はどのような条件でフィルタリングすべきでしょうか？（推奨: セッションID、ブランチ名、作業ディレクトリでの部分一致）」
- 「React Flowのノード配置において、X座標は固定するべきか、動的に計算すべきでしょうか？（推奨: ハーネスはX=0固定、分岐ノードはBranchOffsetX=400）」

### Step 5: 設計の改善

議論の中で以下の状況が発生した場合、詳細設計を改善してください:

- 新しい要件が明確になった
- 設計の矛盾や不整合が発見された
- ユーザーが具体的な改善案を提示した

改善手順:

1. 詳細設計の該当セクションを `docs/detailed-design.md` から読み込む
2. 改善内容をユーザーに確認（プレビュー提示）
3. ユーザーの承認後、`Edit` ツールで修正
4. 修正結果を報告

### Step 6: Issueへのコメント（オプション）

ユーザーがIssueへの書き込みを指示したら:

1. 議論の内容を整理してコメントを作成
2. ユーザーにプレビューを提示して承認を求める
3. 承認された場合のみ、以下のコマンドでIssueにコメントを書き込む:
   ```
   gh issue comment <issue-number> --body "<comment-body>"
   ```
4. 書き込み完了を報告

### コメントテンプレート

Issueにコメントする際は、以下のテンプレートに沿って作成してください:

```markdown
## 検証結果

<!-- 議論・調査の結果わかったこと、確認できた事実を記載 -->

## 更新内容

<!-- 詳細設計に反映した変更点、または今後反映すべき変更点を記載 -->
```
